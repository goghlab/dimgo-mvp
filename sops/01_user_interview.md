# SOP 01 — User Interview (30-min Discovery)

> Ref: Plan §7.2 (W1–W30 mandate) · Plan §3.3 SAM reconfirm.
> Lead: A2 + A5 + A7. Output: `knowledge/interviews/<date>_<handle>.md`.

---

## When to run

- Phase 0 W1–W4: 30 用戶訪談（目標 = 20 個搬過屋 + 10 個叫過師傅）
- Phase 1 / 2: 每月 5–10 個 follow-up
- 任何新人 feature 之前：5 個 target user

## Recruit

| Source | Target |
|--------|--------|
| Personal network | 5 |
| Landing page waitlist | 5 |
| Cold WeChat / WhatsApp | 10 |
| Co-living / estate | 5 |
| Sales 線索現有客戶 | 5 |

> 唔用 paid recruit（會搵錯 persona）。

## Interview structure (30 min)

| Minute | Section | What's asked |
|--------|---------|--------------|
| 0–3 | Warm-up | 你最近搬過屋 / 搵過師傅未？ |
| 3–8 | Last-time experience | 點搵？點決定？咩 app / WhatsApp？最大煩惱？ |
| 8–15 | Behavioural | 用咩設備？幾耐肯等回覆？肯俾幾多 data？ |
| 15–22 | Willingness to delegate | 「如果 AI 幫你跟進，你肯俾幾多 info？邊啲要 human？」 |
| 22–28 | Pricing signal | 「呢個服務你肯俾幾多？」逐步加到 ceiling |
| 28–30 | Hook | 加 waitlist / refer friend |

## Recorder discipline

- Always ask permission: "我會 record，同 anonymize 寫入 summary，可以嗎？"
- 唔錄個人身份敏感資料（身份證 / 地址 / 電話後 4 位）
- Transcript → `knowledge/interviews/<date>_<handle>.md`
- Summary → 1 page max (avoid long documents)

## Output: 1-page synthesis

| Field | Value |
|-------|-------|
| Persona snapshot | 1 line |
| Pain (verbatim top 3) | 3 lines |
| Current workaround | 2 lines |
| DimGo hook (which product/feature) | 1 line |
| Willingness to pay (HK$) | 1 line |
| Trust concerns | 1 line |
| Recommendation | scale 1–5 |

## After synthesis

- 每週二 A2 review
- Tag 為：recurring pattern / one-off / recommend feature
- 為 recruiting quota 用

## Things not to do

- ❌ Mention DimGo brand early（bias 答案）
- ❌ Promise product features（只 pivot based on need）
- ❌ Lead with take rate / pricing as conversation
- ❌ Use leading questions
